# 老手启动器3.0.33更新：Claude汉化线路模型同步与一键导入

> 原文链接：[https://www.laoshoucun.com/jiaocheng/3776](https://www.laoshoucun.com/jiaocheng/3776)

使用老手启动器接入不同的 API 线路时，除了地址和密钥，还需要让 Claude 读到正确的模型名单。如果导入链接里已经指定了模型，保存以后却没有进入实际配置，就容易出现列表不对、模型映射不完整的情况。

这一轮更新围绕线路模型同步和算力中心一键导入展开，完善默认模型、分档映射及接口格式的处理，同时接入老手独立的更新验证机制。下面分别说明模型、导入和升级方面的变化。

这一版更新了什么

新增模型同步：当前线路没有模型名单时尝试读取，并提供手动同步入口；编辑线路时获取的名单可以保存。

模型适配：完善 DeepSeek、GPT 等模型的显示与映射，向上游发送实际模型名，并保留多模型配置。

导入修复：正确接收链接中指定的默认模型、Haiku、Sonnet、Opus 映射、显示名和上下文标记，补齐相关接口格式支持。

启用优化：需要模型映射或协议转换的导入线路使用本地路由；是否立即启用由用户在确认框选择，保存与启用结果分别反馈。

汉化提示修复：遇到已识别的地区不可用页面时显示实际原因，避免提前盖上汉化准备遮罩。

升级机制完善：接入老手独立更新签名与动态更新入口，支持按版本记住「稍后再说」以及针对发生启动或汉化错误的版本分发更新提示。

管理端完善：补齐装机状态、封禁与解封管理，并修复相关后台菜单访问异常。

状态栏右侧的「同步线路模型」：当前线路没有模型名单时，可以从这里读取并保存

使用时可以留意什么

升级说明：3.0.30 及以前的客户端需要先手动覆盖安装 3.0.31 或更高版本一次，才能接入新的独立签名更新链。导入时先核对线路名称、接口格式和模型，再决定是否立即启用；模型名单能够说明账户返回了哪些配置项，实际推理是否可用仍取决于服务商。
